# Flowboard Full-stack Lab PRD

## Goal

验证宜搭 Code Canvas 能否像常规前端工程一样，与运行在本机的 TypeScript HTTP API 完成可观察、可测试、按契约开发的前后端联调。

## User workflow

1. 页面加载后读取服务健康状态和任务列表。
2. 用户按标题搜索、按状态筛选任务。
3. 用户新建任务，并立即在看板中看到服务端返回的数据。
4. 用户将任务在待处理、进行中、已完成之间流转。
5. 用户确认后删除任务。
6. API 不可用、响应不符合契约或浏览器未授权本地网络时，页面显示诊断信息和重试入口。

## Functional contract

- 数据来自 `http://127.0.0.1:4318/api`，不使用前端种子数据冒充联调结果。
- 所有响应通过共享 TypeScript 运行时契约校验。
- 写操作具有 loading 锁；删除需要用户显式确认。
- 请求带 `X-Request-Id`，页面展示最近一次请求 ID，服务端输出结构化日志。
- 页面卸载或筛选变化时取消未完成请求。
- 后端只监听 `127.0.0.1`，并实现 CORS 与 Private Network Access 预检响应。

## Content blocks

1. 页面标题与实验说明。
2. API 在线状态和最近请求 ID。
3. 紧凑任务状态摘要。
4. 新建任务动作区。
5. 搜索与状态筛选工具条。
6. 三列任务看板。
7. 当前选择任务的上下文详情。
8. 契约与本地网络诊断区。

## Acceptance

- API 单元与集成测试通过。
- 前端多文件源码能构建成单个 `.canvas.jsx` 发布产物。
- 无本地目标配置时仍可完成公开仓库构建。
- 页面发布到独立逻辑键 `flowboard.board`，不覆盖其他实验。
- 浏览器授权后，页面能完成读取、新建、状态更新和删除闭环。
